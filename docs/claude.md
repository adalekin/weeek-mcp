# Как подключить weeek-mcp к Claude

Пошаговая настройка для **Claude Desktop** и **Claude Code**. Сервер работает по stdio, так что клиент сам запускает его как подпроцесс — отдельно ничего держать запущенным не нужно.

## 1. Что понадобится

- **Python 3.10+**.
- **API-токен Weeek** — для инструментов задач. Weeek → **Настройки → API** → создать токен.
- **Только для базы знаний:** пакет `weeek-mcp[kb]`, браузер Chromium (используется один раз для входа) и доступ к аккаунту, где эта база знаний открыта.

Задачи и базу знаний можно включить по отдельности или вместе — сервер сам покажет только те инструменты, под которые есть настройки.

## 2. Установка

```bash
# только задачи
pip install weeek-mcp

# задачи + база знаний
pip install "weeek-mcp[kb]"
playwright install chromium
```

Через [uv](https://docs.astral.sh/uv/) как отдельную утилиту (удобно, не мусорит в системном Python):

```bash
uv tool install "weeek-mcp[kb]"
uv tool run --from weeek-mcp playwright install chromium
```

Проверьте, что бинарь виден:

```bash
weeek-mcp --help
```

Если команда не находится — допишите каталог из вывода `pip show -f weeek-mcp` (или `uv tool dir`) в `PATH`, либо укажите в конфиге абсолютный путь до `weeek-mcp`.

## 3. Первый вход в базу знаний (только для KB)

Публичного API у базы знаний нет, поэтому сервер работает через сохранённую сессию браузера. Засейте её один раз — команда откроет браузер, вы входите руками (в том числе через 2FA/SSO/капчу), после чего сессия кешируется для headless-переиспользования:

```bash
weeek-mcp-login
```

Запомните, куда легла сессия (по умолчанию — под `~/.local/state/weeek-mcp/`). Этот путь пригодится ниже как `WEEEK_STORAGE_STATE`.

> Если у аккаунта нет 2FA/капчи, можно вместо этого задать `WEEEK_EMAIL` / `WEEEK_PASSWORD` — тогда сервер войдёт сам при первом обращении.

## 4. Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `WEEEK_API_TOKEN` | Токен API задач. Обязателен для инструментов задач. |
| `WEEEK_EMAIL` / `WEEEK_PASSWORD` | Автоматический вход в KB. Не нужны, если засеяли сессию через `weeek-mcp-login`. |
| `WEEEK_STORAGE_STATE` | Куда кешируется сессия браузера. Укажите абсолютный путь. |
| `WEEEK_WORKSPACE_ID` | ID воркспейса KB. Необязательно — определяется автоматически. |
| `WEEEK_HEADLESS` | `false`, чтобы видеть браузер во время входа. |
| `WEEEK_KB_CACHE_TTL` | Сколько секунд кешировать список документов KB (по умолчанию `300`). |
| `WEEEK_DEBUG_LOG` | `1`/`true` — писать диагностические логи в `~/.local/state/weeek-mcp/debug.log` (некоторые клиенты глотают stderr). По умолчанию выключено. |

Для задач достаточно одного `WEEEK_API_TOKEN`. Для базы знаний добавьте `WEEEK_STORAGE_STATE` (и, при желании, `WEEEK_EMAIL`/`WEEEK_PASSWORD`).

## 5. Claude Desktop

Откройте конфиг:

- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

(Или через приложение: **Settings → Developer → Edit Config**.)

Добавьте сервер в `mcpServers`:

```json
{
  "mcpServers": {
    "weeek": {
      "command": "weeek-mcp",
      "env": {
        "WEEEK_API_TOKEN": "ваш_токен",
        "WEEEK_STORAGE_STATE": "/абсолютный/путь/до/storage_state.json"
      }
    }
  }
}
```

Только задачи — оставьте один `WEEEK_API_TOKEN` и уберите строку `WEEEK_STORAGE_STATE`. Если `weeek-mcp` не в `PATH`, впишите в `command` абсолютный путь до бинаря.

Полностью перезапустите Claude Desktop (закрыть и открыть заново). После перезапуска в диалоге появится значок инструментов — Weeek будет там.

## 6. Claude Code

Одной командой (env через `-e`, команда сервера — после `--`):

```bash
claude mcp add weeek -s user \
  -e WEEEK_API_TOKEN=ваш_токен \
  -e WEEEK_STORAGE_STATE=/абсолютный/путь/до/storage_state.json \
  -- weeek-mcp
```

- `-s user` — сервер будет доступен во всех проектах. Замените на `-s project` (запишется в `.mcp.json` репозитория, шарится с командой) или `-s local` (только этот проект, по умолчанию).
- Только задачи — уберите строку с `WEEEK_STORAGE_STATE`.

Проверка:

```bash
claude mcp list      # weeek должен быть в списке
```

Внутри сессии список подключённых серверов и их инструменты видно по команде `/mcp`.

## 7. Проверка, что всё работает

Попросите Claude:

> Покажи мои проекты в Weeek

Под капотом вызовется `weeek_list_projects` (или сначала `weeek_whoami`). Вернулись проекты — задачи подключены.

Для базы знаний:

> Найди в базе знаний Weeek документ про onboarding и покажи его содержимое

В Claude Desktop документы KB также доступны как вложения: меню **+** у подключённого сервера → выбираете документ → в контекст попадает его **содержимое**, а не ссылка.

## 8. Если что-то не так

- **Инструментов Weeek не видно.** Сервер показывает задачи только при заданном `WEEEK_API_TOKEN`, а KB — только при наличии логина или засеянной сессии. Проверьте `env` в конфиге и что клиент перезапущен.
- **`weeek-mcp: command not found`.** Бинарь не в `PATH` — укажите в конфиге абсолютный путь (найти: `pip show -f weeek-mcp` или `uv tool dir`).
- **KB отвечает ошибкой входа.** Сессия истекла или не засеяна — прогоните `weeek-mcp-login` заново. Для аккаунтов с 2FA/SSO автологин по `WEEEK_EMAIL`/`WEEEK_PASSWORD` не сработает, только `weeek-mcp-login`.
- **Непонятно, что происходит.** Включите `WEEEK_DEBUG_LOG=1` и смотрите `~/.local/state/weeek-mcp/debug.log` — там пошаговый лог с таймингами (полезно, когда клиент прячет stderr).
